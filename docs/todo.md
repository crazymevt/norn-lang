# Norn TODO

## Standard library

- [x] **Command-line parsing (`norn.cli`).** A spec map describes options (typed, with choices, defaults, environment variables, required, repeatable, counted, negatable), positional arguments (optional, variadic), and nested subcommands that inherit their parents' options. `parse` returns the parsed map or signals `UsageError`, with did-you-mean suggestions. `usage` generates the help, and `run` prints help or the error (status 2) or calls the command's `:run`. A new `norn.sys/program-args` returns a script's or image's own arguments. Written in Norn. [Command-line programs](reference/libraries.md#command-line-programs)
- [x] **Stream and filesystem helpers (`norn.io`).** `read-exactly`, `copy-stream!` with `:limit`, `text-reader` and `read-chunk` over the incremental decoder, `temp-file`, `temp-directory` and their `with-` forms, and `write-atomic!` and `with-atomic-file` (a flushed file beside the target, renamed over it). New primitives: the `:create-new` open mode, `sync!` on a handle, directory sync, and an exclusive `mkdir`. [I/O and the system](reference/libraries.md#io-and-the-system)
- [x] **Named time zones and calendar arithmetic (`norn.time`).** Zones come from the system's TZif files (`$TZDIR` or `/usr/share/zoneinfo`), parsed in Norn with each file's POSIX TZ rule for later dates; `$TZ` and `/etc/localtime` give `system-zone`. `ZonedDateTime` (`in-zone`, `zoned`, `format-zoned`/`parse-zoned` in RFC 9557 text) resolves skipped and repeated wall-clock times by `:resolve` — `:compatible`, `:earlier`, `:later` or `:reject`, as in Temporal. `shift` moves dates along the calendar (month ends clamp) and zoned times by date units on the wall clock and time units on the time line; `days-between`, `months-between`, `weekday`, `day-of-year`, `start-of-day`. Date math is in whole days, so years 0–9999 work. Tests skip the named zones where no zone files exist. [Time zones and calendar arithmetic](reference/libraries.md#time-zones-and-calendar-arithmetic)
- [x] **Host terminal support (`norn.terminal`).** OS primitives for `isatty`, the window size, raw mode (`cfmakeraw` with output processing kept; restored on exit) and timed byte reads from standard input. In Norn: `tty?`, `size`, `color-support` (`NO_COLOR`, `FORCE_COLOR`, `COLORTERM`, `TERM`), `style` with attributes and 16, 256 or RGB colors brought down to what the terminal shows, `strip` and `width`, cursor and screen control, `with-raw-mode` (with alternate screen, hidden cursor, mouse and bracketed paste), and `read-key` over `decode-keys`: xterm sequences with modifiers, function keys, Alt, CSI u, SGR mouse, bracketed paste and UTF-8, a lone Escape after 50 ms. `suspend!` for Ctrl-Z (SIGTSTP, now in `norn.signal`) restores the terminal and comes back to raw mode on `fg`; `:keyboard` and `keyboard-on` use the kitty keyboard protocol. Tested on a real pseudo-terminal and under zsh job control. `norn.sys/info` has `:executable`. [The terminal](reference/libraries.md#the-terminal)
- [x] **HTTP client streaming and multipart forms (`norn.http`).** `:as :stream` gives the response body as a `norn.io` stream (`ResponseBody`: by length, chunked, or until the connection closes), read with every stream function and usable as another request's body; read to its end, the connection goes back to the pool, closed early (`io/close`, or `with-response`), it closes. `:multipart` and `multipart` send `multipart/form-data` (text, bytes, files and streams; whole bodies with a length, streamed ones chunked); `multipart-params` parses one, with RFC 8187 file names. `norn.io` gained `stream-read`, `stream-write` and `stream-close` generics so classes can be streams, and a `%bytes-find` primitive. [HTTP bodies and forms](reference/libraries.md#http-bodies-and-forms)
- [x] **Property-based testing (`norn.property`).** Generators that record their random draws, `for-all` with bindings that can use earlier values, `check` and `defproperty` (a `deftest`), and shrinking that edits and replays the draws: it removes runs of draws, lowers a length together with an item, moves values toward 0, and moves value between draws. A seed reproduces a failure's cases. `property_test.norn` holds round-trip properties for JSON, JSON Lines, EDN, `norn.bin`, CBOR, YAML, Decimal text, packed buffers, hex and base64. [Properties](tooling.md#properties)
- ~~**TAR archives (`norn.tar`).**~~ Dropped on 2026-11-15: not needed. `norn.zip` and `norn.compress` cover archives for now.

## Language and runtime gaps for review

Review stack safety first. Settle the core API changes before sealing `norn.core`.

- [x] **Make structural operations safe on deep values.** Printing, equality, hashing and `compare` walk values with explicit stacks instead of native recursion, so a vector, list or map nested a million deep (built in code, past the reader's limit) prints, compares and hashes. Hash values are unchanged. Regressions in `core_test.norn`. [Printer](../crates/norn-rt/src/print.rs), [equality and hashing](../crates/norn-rt/src/equal.rs)
- [x] **Let library-defined collections implement core operations.** A class defines methods on `collection-seq` (required), `collection-count` and `collection-nth`, generic functions in `norn.core`. `seq`, `count`, `nth`, `first`, `rest`, `next`, `vec` and `set` call them only for instances, handing the call to the interpreter so methods run in the fiber and their errors reach the caller. Built-in collections keep their fast paths. `norn.buffer/Buffer` is the first implementation. [Collections a class defines](reference/objects.md#collections-a-class-defines)
- [x] **Add owned mutable packed buffers.** `norn.buffer/MutableBuffer` is a `(:mutable)` object over a new `ByteArray` runtime kind, written in place with `set!`, `fill!` and `copy!`, and read as a collection. Its owner fiber alone uses it, and `release!` or a channel send hands it on. `freeze!` retags the storage as immutable `Bytes` without copying, and `snapshot` copies. [Packed buffers](reference/libraries.md#bytes-and-packed-buffers)
- [x] **Decide how library-defined numbers participate in core arithmetic.** They don't: `Decimal` keeps its own functions (`add`, `compare`, `quantize`…), and `+`, `<`, `==` and `number?` cover only the core tower of integers, ratios and floats, which compare exactly with each other. [Decimal values](reference/libraries.md#decimal-values)

### Additional sealing blockers

- [x] **Keep contract checking consistent across cold and warm module loads.** The contract mode is part of the module cache key, so code expanded under `:none` never loads under `:boundaries`. Tested against one cache under both modes (`cache_test.norn`). [Module cache](../lib/compiler/expander.norn)
- [x] **Preserve hash-key lookup across live class redefinition.** An instance hashes by its slots that don't hold their class's default, in any order, so adding a defaulted slot or reordering slots keeps existing keys findable. Equality is unchanged: an old instance reads a new slot's default, so it equals a new instance with that value. Changing a slot's default changes the hash of instances holding the old or new default. Tested in `clos_test.norn`. [Equality and hashing](../crates/norn-rt/src/equal.rs)
- [x] **Detect circular module loads across fibers.** Each load records the fiber running it, and a fiber about to wait for another's load follows the chain of waits; reaching itself is a circular require, reported as an error instead of waiting forever. Tested with both loads started concurrently (`module_test.norn`). [Module loader](../lib/core/core.norn)
- [x] **Make mixed numeric ordering consistent.** A float compares with an integer or ratio by its exact value, so `compare`, `sort`, `<` and `==` are transitive across categories, and sorted collections can't find `2^53 + 1` through the float `2^53`. `(== 1/3 0.3333333333333333)` is now false. Tested in `core_test.norn`. [Numeric comparisons](../crates/norn-vm/src/numeric.rs)

### Other review items

- [x] **Propagate early termination through `cat`.** `cat` keeps the `reduced` signal through its inner reduction, so `(comp cat (take 1))` stops after the first group, and `mapcat` stops on an infinite input. Tested in `core_test.norn`. [Transducer implementation](../lib/core/core.norn)
- [x] **Define export removal on module reload.** `require :reload` removes the module's own names its source no longer defines. Code already compiled against a removed var keeps calling it; new code can't refer to it. The exports a module's current source defines (what `ns-publics` shows after its last load) are its baseline for sealing and API compatibility checks. Tested in `module_test.norn`. [Module loader](../lib/core/core.norn)
- [x] **Drive a UI event loop from Norn code.** `:main-thread` foreign functions run on the process's first thread under stock `norn` (see the main-thread lane in [runtime.md](runtime.md)). The program owns its loop and pumps events with main-thread calls: `norn-sdl3` opens windows, polls events, and shuts down on the main thread with no native helper, and `norn-raylib` works the same way. A toolkit whose own loop never returns (winit's `run_app`, `NSApplication run`) would still need a pump-style entry point. [Main-thread lane](../crates/norn-vm/src/main_lane.rs)

Module sealing and API compatibility checks are tracked in the [M8](plan-m8.md) and [M9](plan-m9.md) plans.
