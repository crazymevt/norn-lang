# Skein TODO

## Standard library

- [x] **Command-line parsing (`skein.cli`).** A spec map describes options (typed, with choices, defaults, environment variables, required, repeatable, counted, negatable), positional arguments (optional, variadic), and nested subcommands that inherit their parents' options. `parse` returns the parsed map or signals `UsageError`, with did-you-mean suggestions. `usage` generates the help, and `run` prints help or the error (status 2) or calls the command's `:run`. A new `skein.sys/program-args` returns a script's or image's own arguments. Written in Skein. [Command-line programs](../reference/libraries.md#command-line-programs)
- [x] **Stream and filesystem helpers (`skein.io`).** `read-exactly`, `copy-stream!` with `:limit`, `text-reader` and `read-chunk` over the incremental decoder, `temp-file`, `temp-directory` and their `with-` forms, and `write-atomic!` and `with-atomic-file` (a flushed file beside the target, renamed over it). New primitives: the `:create-new` open mode, `sync!` on a handle, directory sync, and an exclusive `mkdir`. [I/O and the system](../reference/libraries.md#io-and-the-system)
- [x] **Named time zones and calendar arithmetic (`skein.time`).** Zones come from the system's TZif files (`$TZDIR` or `/usr/share/zoneinfo`), parsed in Skein with each file's POSIX TZ rule for later dates; `$TZ` and `/etc/localtime` give `system-zone`. `ZonedDateTime` (`in-zone`, `zoned`, `format-zoned`/`parse-zoned` in RFC 9557 text) resolves skipped and repeated wall-clock times by `:resolve` — `:compatible`, `:earlier`, `:later` or `:reject`, as in Temporal. `shift` moves dates along the calendar (month ends clamp) and zoned times by date units on the wall clock and time units on the time line; `days-between`, `months-between`, `weekday`, `day-of-year`, `start-of-day`. Date math is in whole days, so years 0–9999 work. Tests skip the named zones where no zone files exist. [Time zones and calendar arithmetic](../reference/libraries.md#time-zones-and-calendar-arithmetic)
- [x] **Host terminal support (`skein.terminal`).** OS primitives for `isatty`, the window size, raw mode (`cfmakeraw` with output processing kept; restored on exit) and timed byte reads from standard input. In Skein: `tty?`, `size`, `color-support` (`NO_COLOR`, `FORCE_COLOR`, `COLORTERM`, `TERM`), `style` with attributes and 16, 256 or RGB colors brought down to what the terminal shows, `strip` and `width`, cursor and screen control, `with-raw-mode` (with alternate screen, hidden cursor, mouse and bracketed paste), and `read-key` over `decode-keys`: xterm sequences with modifiers, function keys, Alt, CSI u, SGR mouse, bracketed paste and UTF-8, a lone Escape after 50 ms. `suspend!` for Ctrl-Z (SIGTSTP, now in `skein.signal`) restores the terminal and comes back to raw mode on `fg`; `:keyboard` and `keyboard-on` use the kitty keyboard protocol. Tested on a real pseudo-terminal and under zsh job control. `skein.sys/info` has `:executable`. [The terminal](../reference/libraries.md#the-terminal)
- [x] **HTTP client streaming and multipart forms (`skein.http`).** `:as :stream` gives the response body as a `skein.io` stream (`ResponseBody`: by length, chunked, or until the connection closes), read with every stream function and usable as another request's body; read to its end, the connection goes back to the pool, closed early (`io/close`, or `with-response`), it closes. `:multipart` and `multipart` send `multipart/form-data` (text, bytes, files and streams; whole bodies with a length, streamed ones chunked); `multipart-params` parses one, with RFC 8187 file names. `skein.io` gained `stream-read`, `stream-write` and `stream-close` generics so classes can be streams, and a `%bytes-find` primitive. [HTTP bodies and forms](../reference/libraries.md#http-bodies-and-forms)
- [x] **Property-based testing (`skein.property`).** Generators that record their random draws, `for-all` with bindings that can use earlier values, `check` and `defproperty` (a `deftest`), and shrinking that edits and replays the draws: it removes runs of draws, lowers a length together with an item, moves values toward 0, and moves value between draws. A seed reproduces a failure's cases. `property_test.skn` holds round-trip properties for JSON, JSON Lines, EDN, `skein.bin`, CBOR, YAML, Decimal text, packed buffers, hex and base64. [Properties](../tooling.md#properties)

## Language and runtime gaps for review

Review stack safety first. Settle the core API changes before sealing `skein.core`.

- [x] **Make structural operations safe on deep values.** Printing, equality, hashing and `compare` walk values with explicit stacks instead of native recursion, so a vector, list or map nested a million deep (built in code, past the reader's limit) prints, compares and hashes. Hash values are unchanged. Regressions in `core_test.skn`. [Printer](../../crates/skein-rt/src/print.rs), [equality and hashing](../../crates/skein-rt/src/equal.rs)
- [x] **Let library-defined collections implement core operations.** A class defines methods on `collection-seq` (required), `collection-count` and `collection-nth`, generic functions in `skein.core`. `seq`, `count`, `nth`, `first`, `rest`, `next`, `vec` and `set` call them only for instances, handing the call to the interpreter so methods run in the fiber and their errors reach the caller. Built-in collections keep their fast paths. `skein.buffer/Buffer` is the first implementation. [Collections a class defines](../reference/objects.md#collections-a-class-defines)
- [x] **Add owned mutable packed buffers.** `skein.buffer/MutableBuffer` is a `(:mutable)` object over a new `ByteArray` runtime kind, written in place with `set!`, `fill!` and `copy!`, and read as a collection. Its owner fiber alone uses it, and `release!` or a channel send hands it on. `freeze!` retags the storage as immutable `Bytes` without copying, and `snapshot` copies. [Packed buffers](../reference/libraries.md#bytes-and-packed-buffers)
- [x] **Decide how library-defined numbers participate in core arithmetic.** They don't: `Decimal` keeps its own functions (`add`, `compare`, `quantize`…), and `+`, `<`, `==` and `number?` cover only the core tower of integers, ratios and floats, which compare exactly with each other. [Decimal values](../reference/libraries.md#decimal-values)

### Additional sealing blockers

- [x] **Keep contract checking consistent across cold and warm module loads.** The contract mode is part of the module cache key, so code expanded under `:none` never loads under `:boundaries`. Tested against one cache under both modes (`cache_test.skn`). [Module cache](../../lib/compiler/expander.skn)
- [x] **Preserve hash-key lookup across live class redefinition.** An instance hashes by its slots that don't hold their class's default, in any order, so adding a defaulted slot or reordering slots keeps existing keys findable. Equality is unchanged: an old instance reads a new slot's default, so it equals a new instance with that value. Changing a slot's default changes the hash of instances holding the old or new default. Tested in `clos_test.skn`. [Equality and hashing](../../crates/skein-rt/src/equal.rs)
- [x] **Detect circular module loads across fibers.** Each load records the fiber running it, and a fiber about to wait for another's load follows the chain of waits; reaching itself is a circular require, reported as an error instead of waiting forever. Tested with both loads started concurrently (`module_test.skn`). [Module loader](../../lib/core/core.skn)
- [x] **Make mixed numeric ordering consistent.** A float compares with an integer or ratio by its exact value, so `compare`, `sort`, `<` and `==` are transitive across categories, and sorted collections can't find `2^53 + 1` through the float `2^53`. `(== 1/3 0.3333333333333333)` is now false. Tested in `core_test.skn`. [Numeric comparisons](../../crates/skein-vm/src/numeric.rs)

### From the performance survey

The [survey](../internals/perf-survey.md) (2026-11-15) found two items that change what callers can see, and two cheap fixes worth doing soon. The rest wait for M10 and M11.

- [x] **Make the line and text readers opaque.** `line-reader` and `text-reader` return `LineReader` and `TextReader` objects. A line reader is a stream too: `read` gives what it holds past the last line, then the stream's. [Survey A1](../internals/perf-survey.md#a-settle-before-sealing)
- [x] **Decide whether release builds check signatures.** They do: checking at module boundaries is part of a signature's meaning, and `*check-contracts* :none` stays as an explicit opt-out. Recorded in [design §8.4](../internals/design.md#84-types-decided). [Survey A2](../internals/perf-survey.md#a-settle-before-sealing)
- [x] **Make checked signatures cheap.** A checked call from another module costs 0.79 µs at tier 0 and 0.58 µs at tier 1, down from 4.1 µs and 3.5 µs. The wrapper has fixed arities that check in place, reads its contract from a var it finds once, builds messages only on failure, and tests classes and predicates directly. Inlining the checks is M10's. [Survey B1](../internals/perf-survey.md#b-fixable-later-by-impact)
- [x] **Fix quadratic buffering and the rope's slices.** The line reader, the HTTP connection reader and the streamed body keep an offset into their buffer and copy what's unread only when they read more: reading 20,000 lines takes 22 ms, down from 1.6 s. The rope's `slice` reads the leaves in range, `line` reads forward from its start, and an edit within one leaf rebuilds only its path: 20,000 line lookups take 309 ms (was 2.4 s), and 1,000 inserts 26 ms (was 100 ms). A property test checks rope edits against strings. [Survey B2](../internals/perf-survey.md#b-fixable-later-by-impact)

- [ ] **Waking fibers on other carriers is expensive.** A fan-out of 500 lines to 40 fibers through channels (bench/programs.skn's chat) takes about 4.5 ms on one carrier and about 64 ms on ten, and with the other programs in the same process it swung between 12 and 59 ms. Each `put!` that wakes a fiber parked on another carrier seems to cost tens of microseconds (a futex wake, a queue hand-off, a cold cache); worth a profile with `SKEIN_THREADS` from 1 to 10, and a look at keeping a woken fiber where it was. Found making M10's baseline. **Partly done (2026-11-17):** measured, the fan-out took 2.4 ms on one carrier, 4.4 on two, 8.2 on four and 45 on ten. Most of it was `schedule` waking a sleeping carrier, a system call for each `put!` that woke a fiber, and each carrier woken going straight back to sleep. A carrier out of work now looks for more for 50 µs before it sleeps (`spin_for_work`, at most half the carriers at once), and while one is looking, making a fiber runnable wakes nobody; a count of queued fibers lets a carrier with nothing to find skip every queue's lock. Ten carriers: 45 → 15 ms; ping-pong (200,000 fibers, ten rounds) 2.2 → 1.8 s; the other programs, ten fibers summing in parallel and a loop of sleeps are as they were. **Left:** it's still 2× on two carriers and 6× on ten: a fiber woken is run by another carrier for a microsecond of work, with the channel's and the queue's locks passed between cores. Tried and no better: one spinner (31 ms), every carrier spinning (20), 200 µs, stealing half a queue, thieves skipping a held queue. What's left to try is keeping a woken fiber on its waker's carrier for a short while before it can be stolen (Go's `runnext`).

### Windows, before sealing

Reviewed on 2026-11-15 for interfaces whose meaning is POSIX-only. Windows itself is M12; adding Windows-only functions or options later is a minor change, so only these needed settling now.

- [x] **Make the FFI's `:long` and `:ulong` mean C's `long`.** They were aliases of `:i64` and `:u64`, but C's `long` is 32 bits on Windows (LLP64), so a C `long` declared `:long` would have been passed wrongly there. Now they follow the platform; `:i64` and `:u64` stay 64 bits everywhere. Nothing changes on macOS or Linux. Tested with `labs` in `ffi_test.skn`. [FFI types](../../lib/skein/ffi.skn)
- [x] **Report a child's signal by name.** `process/wait` gave `:signal` as the raw number, which differs between platforms (`SIGUSR1` is 30 on macOS and 10 on Linux), while `kill` and `signal/listen` take keywords. It now gives `:term`, `:kill`, `:int`, `:segv` and so on, from one table that `kill` and `listen` share, and a number only for a signal without a name. `listen` refuses `:segv`, `:bus`, `:ill`, `:fpe` and `:trap` by name, as it did `:kill` and `:stop`. [Processes](../../lib/skein/process.skn)
- [x] **Say what the OS doesn't have.** `signal/listen`, `raise` and `process/kill`: a signal the OS lacks is an error (on Windows only `:int` is there to listen for, and `kill` with `:term` or `:kill` ends the process). `fs/glob` patterns divide segments with `/` on every OS. `read-text` leaves line endings as they are; `lines` splits at `\n` or `\r\n`.

Fine as they are, for M12's implementation: `io/info` reports `:readonly`, not mode bits; paths are joined by the runtime; zones need bundled zone files and the registry's zone on Windows (`zone-directories` can name them); the terminal uses the console's VT mode, and `suspend!` already doesn't stop where nothing can resume it; a pty is ConPTY; `skein package` gains a target.

- [x] **The heap is about thirty times its live data under a store taking writes, and M11 should start there.** Fixed by M11 (2026-11-18: objects move, generations by default; 2.2× on stash). Found with bench/stash.skn on 2026-11-18, and measured since with `(gc-stats)`' `:live-bytes` beside `:heap-bytes`. stash with 44,000 keys has 25 MB of live objects on 715 MB of pages (level from 45 s to 180 s); with 440,000, 200 MB on several GB and still rising after 150 s, towards the same ratio. Why: the collector never moves an object, so a page stays in use while anything on it lives, and between one write and the next the server makes 15 KB or so of garbage (requests read, replies written). Each value written, a few hundred bytes that live until the key is written again, ends up nearly alone on its 32 KB block: the pages in use are about the number of live values times half a block. What was ruled out: a string's size (a 100-character string is 128 bytes, under Immix's 256-byte line, so it does refill holes; the 290 said before was pages, not objects); the benchmark client's own allocations (without its histogram's vectors, the same 719 MB); a leak (reads alone, and writes made without the network's garbage between them, hold steady); the growth policy (fixed, runtime.md §4.1: it fed this, but isn't it). MMTk's mark-sweep plan (`SKEIN_GC_PLAN=marksweep`: freed cells reused by size) does better but not well: 520 MB against 715, at 20% fewer requests a second; a loop overwriting a map's values with no garbage between holds 2× its live data under it and 4× under Immix. So no allocator that leaves objects where they were made fixes this: what lives has to be gathered. **For M11's plan:** a young generation that is copied (what survives a collection or two is moved together, out from among the garbage) answers this and the pauses at once, and needs objects to move only while young; or Immix's own defragmentation, moving what's on sparse blocks. Either way the plan starts with what assumes an object stays put: the interpreter's cached code and frame addresses, compiled code holding constants' addresses, `%identity-hash` (the compiler's constant index goes by it), buffers handed to C unpinned. In its favour: a collection only happens at a safepoint, where every live value is in a heap frame the collector scans exactly, so roots can be rewritten. Smaller, found on the way: a two-item vector is 112 bytes (stash's `[value expires]` entry, one a key).

- [x] **Two editors' requests crossed (2026-11-16).** Each editor numbers its own requests, but the server knew a running request by its id alone: with two editors connected, `:interrupt :target 3` found whichever request 3 was running, one finishing forgot the other's, and printed output (`{:event :out :id 3}`) went to every connection.
